# 迭代小组平台 1.1.0 升级说明

适用对象：已在用的安装（1.0.1 / 1.0.2 / 1.0.3 / 1.0.4 / 1.1.0-rc1～rc4）。全新安装请直接用全量包
`iteration-board-offline-1.1.0.zip` 按随包《部署手册》安装，不看本文。

## 一、选哪个包

| 当前版本 | 用哪个包 |
| --- | --- |
| 1.1.0-rc4 | `iteration-board-patch-1.1.0-rc4-to-1.1.0.zip` |
| 1.0.4 | `iteration-board-patch-1.0.4-to-1.1.0.zip` |
| 1.0.2 / 1.0.3 | 同 1.0.4：用 `iteration-board-patch-1.0.4-to-1.1.0.zip`（这两个版本的程序布局与 1.0.4 相同，脚本会把它们识别为 1.0.4 并照常升级，数据库在新版首次启动时自动向前迁移） |
| 1.0.1 及更早 | 不再提供补丁包：先用迁移脚本（`migrate-export.bat`）导出数据，全新安装 1.1.0 后用 `migrate-import.bat` 导入；或联系管理员 |
| 1.1.0-rc1 / rc2 / rc3 | 先打历史补丁升到 rc4（如 rc3→rc4 补丁），再用 rc4 的包；或用全量包全新安装后，用随包的迁移脚本（`migrate-export.bat` / `migrate-import.bat`）把旧数据搬过去 |
| 还没装过 | 全量包 `iteration-board-offline-1.1.0.zip` 全新安装 |

补丁包与全量包的核心程序逐字节一致（发布时已做 SHA-256 比对），不存在「补丁版功能少」的问题。

## 二、升级步骤（补丁包）

1. 把补丁 zip 解压到一个普通文件夹（不要在 zip 里直接双击脚本）。
2. 双击里面的 `apply-patch.bat`，或在命令行运行 `apply-patch.bat <安装目录>`。
   - 不带参数运行时，脚本会尝试从已注册的服务自动找到安装目录；找到唯一一个会显示出来让你确认，找不到或有多个时会请你手动输入。
   - 脚本会自动请求管理员权限；路径里有空格、括号都没关系。
3. 脚本会依次：校验安装目录与补丁文件 → **自动备份数据库**（服务运行中当场做一次全新备份）→ 记录旧程序 → 停服务 → 等旧程序完全退出 → 覆盖程序 → 启服务 → 自检。全程有日志文件（脚本同目录，文件名带时间戳）。
4. 浏览器打开平台，版本号显示 1.1.0、能正常登录即升级完成。第一次登录新版会弹一次「版本更新说明」，看完点「知道了」即可。

## 三、升级前自动备份与回滚（重要）

打补丁前脚本自动做两份备份，缺一不继续：

- **数据库**：由补丁脚本**当场做一次全新备份**（pg_dump 自定义格式，存进备份目录，目录位置见 `config\application.yml` 的 `backup.dir`，默认安装目录下 `backup\`）。不复用已有备份、也不依赖安装目录里的旧版 `backup.bat`（老版本的备份脚本格式与新版不同）。备份失败，脚本停下报错，不动任何文件。若数据库服务没在运行，脚本会先尝试把它启动起来再备份。
- **旧程序**：补丁将要覆盖的全部文件（含全部脚本）先逐份复制，再加整个 `app\` 目录，一并存进备份目录下的 `upgrade-<日期时间>\` 文件夹（其中 `upgrade-info.txt` 记录了数据库备份的位置与升级前版本）。老安装（1.0.1 / 1.0.2 / 1.0.3 / 1.0.4）本身没有 `version.txt`，备份里自然也没有，不影响回滚。

万一升级后要回滚，**首选一键脚本**：在安装目录运行 `rollback.bat`（老版本升级时补丁已把这个脚本放进安装目录）。它自动找到最近一次升级的 `upgrade-<日期时间>\` 备份包，先给当前状态再做一次安全备份，然后把程序文件和数据库一起还原，并处理 `version.txt` 残留（老版本回滚后不会残留新版的版本标记）。回滚完成后启服务确认版本与数据。

也可以手工回滚（脚本不可用时兜底）：

1. 停应用服务（`stop.bat`）。
2. 数据库：运行 `restore.bat`，选择 `upgrade-info.txt` 里记录的那个升级前数据库备份恢复；或直接用精确命令（先确保应用服务已停、没有其他连接在用库）：把配置里的数据库密码设进环境变量后执行
   `runtime\pgsql\bin\pg_restore.exe -h 127.0.0.1 -p 15432 -U postgres --clean --if-exists -d iteration_board <备份目录>\db.dump`
3. 程序：把 `upgrade-<日期时间>\files\` 里的文件按相对路径覆盖回安装目录；**若该文件夹里没有 `version.txt`，务必把安装目录里的 `version.txt` 删掉**（那是升级时新版写入的，留着会让旧程序顶着新版本号，后续补丁会被版本校验拒绝）。
4. 启服务（`start.bat`），确认回到旧版本、数据完好。

注意：**数据库升级后不能只换回旧程序**——必须程序和数据库一起回滚，否则旧程序读不了新结构。

## 四、不会被动到的东西

- `config\application.yml`（你的配置，含 AI 接口等设置）**永远不被补丁覆盖**：补丁包里带了新版模板也只会跳过并打 `[WARN]` 提示。1.1.0 相对 1.0.4 新增的配置项只有两处，**都是可选项、不补也能正常启动**（程序内置了相同默认值）：① 接口文档开关 `springdoc.api-docs.enabled` / `springdoc.swagger-ui.enabled`（默认 `false`，保持关闭即可）；② 备份目录 `backup.dir`（默认空 = 安装目录下 `backup\`，想把备份放到别的盘再改）。也就是说，**旧配置文件一个字不改也能通过新版启动自检**。
- 数据库数据、上传的文件、备份文件都不在补丁覆盖范围内；反馈图片存在数据库里，随数据库备份一起走。
- 用户账号与密码不变、不强制改密；但注意 1.1.0 的密码规则加强只对「新设的密码」生效，老密码照常能登录。老管理员账号不会被自动降权，升级后建议人工复核一遍平台管理员名单。
- 补丁会把安装目录里的全部脚本（`backup.bat`、`reset-admin.bat`、`rollback.bat` 等 12 个）一并更新到 1.1.0 的新版，旧脚本已随升级前备份留存（见上一节）。

## 五、常见提示

- **Windows SmartScreen / 杀毒软件拦截**：脚本与程序未做商业代码签名，首次运行可能弹「Windows 已保护你的电脑」——点「更多信息 → 仍要运行」即可；这是未签名软件的例行提示，不代表文件有问题（可用 SHA256SUMS.txt 核对文件完整性）。
- **双击脚本一闪而过**：1.1.0 起脚本带防闪退外壳，正常情况不会再发生；若仍闪退，请在脚本目录打开命令行手动运行同名脚本，窗口会保留报错信息，日志文件也在同目录。
- **升级后页面还是旧样子**：浏览器强制刷新一次（Ctrl+F5）；长期开着的旧标签页请关掉重开。
- **更新说明弹窗关不掉**：1.1.0 已修（弹窗限高 + 内部滚动）；若在矮屏上仍异常，先按 Esc 或刷新页面，再到「系统信息页」里重看更新说明。
