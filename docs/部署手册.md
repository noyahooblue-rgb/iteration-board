# 迭代小组平台 · 部署手册

本手册面向负责安装和维护本平台的管理员。平台以 Windows 离线安装包交付，不需要联网、不需要预装数据库或 Java 环境，包内自带全部运行时。

## 1. 环境要求

| 项目 | 要求 |
| --- | --- |
| 操作系统 | 64 位 Windows 10 / 11，或 Windows Server 2016 及以上 |
| CPU / 内存 | 2 核 / 4 GB 以上（推荐 4 核 / 8 GB） |
| 磁盘 | 安装包解压后约需 2 GB，另预留数据与备份空间（建议 20 GB 以上） |
| 权限 | 安装、启停、卸载需本机管理员权限 |
| 网络 | 安装不需要联网；局域网访问需放行应用端口（默认 18080，见第 6 节） |

说明：VC++ 2015-2022 x64 运行库自 1.0.2 起以 DLL 形式随包部署（放在 `runtime\pgsql\bin` 等目录内，紧挨使用它们的程序），不需要在系统里安装任何运行库，install.bat 只做齐全性检查。

## 2. 获取安装包（分卷合并与校验）与解压路径

安装包 1.0.1 起以**分卷**形式交付（单文件大小受限的传输通道无法放行约 200 MB 的完整包）：

1. 拿到的文件应包括：`iteration-board-offline-1.0.1.zip.001`、`.002`、`.003`（共 3 卷，每卷不超过 98 MB）、`合并.bat`、`SHA256SUMS.txt`、`分卷说明.txt`。缺任何一卷都无法合并。
2. 把全部分卷与 `合并.bat` 放到**同一个文件夹**，双击 `合并.bat`：它用系统自带的 `copy /b` 按顺序合并出 `iteration-board-offline-1.0.1.zip`，并用系统自带的 `certutil` 校验 SHA-256 与 `SHA256SUMS.txt` 比对。屏幕显示「校验通过」才可继续；显示失败时不要安装，重新拷贝出错的分卷后再合并。
3. 装有 7-Zip 的机器也可跳过 `合并.bat`：直接右键 `.001` 卷解压，7-Zip 会自动读取后续分卷（校验仍建议按 `SHA256SUMS.txt` 核对一次）。
4. 把合并出的 `iteration-board-offline-1.0.1.zip` 解压到**只含英文、数字和空格**的路径，例如 `D:\IterationBoard`。安装目录里只要出现中文等非英文字符，`install.bat` 会在动手安装前直接拦下并提示换路径（数据库 PostgreSQL 在 Windows 上处理不了这类路径，硬装会失败在初始化一半的地方）；空格可以保留，但建议不用。

注：1.0.1 之后的小版本修复以**增量补丁**交付（见「安装包/补丁」目录），全量包只在里程碑版本重新出。补丁的用法见每个补丁自带的《补丁说明》：解压覆盖到安装目录后，按说明重跑 `install.bat` 或 `apply-patch.bat` 即可，不需要重新下载全量包。
5. 解压后根目录应包含：`install.bat`、`start.bat`、`stop.bat`、`backup.bat`、`restore.bat`、`upgrade.bat`、`uninstall.bat`，以及 `app\`、`runtime\`、`config\`、`data\`、`backup\`、`logs\`、`docs\`、`service\` 文件夹。缺文件说明解压不完整，请重新解压。

## 3. 安装步骤

1. 右键 `install.bat` →「以管理员身份运行」。
2. 脚本依次自动完成：
   - 安装路径字符检查：只允许英文、数字和空格，含中文等非英文字符会明确报错并停止，不做任何改动（已装好的老安装升级/打补丁时只警告、不拦截）；
   - 管理员权限自检；
   - 检查包内 VC++ 运行库 DLL 是否齐全（随包部署，不做系统安装；缺失会逐个列出缺哪个文件并中止）；
   - 生成随机数据库口令并写入 `config\application.yml`（请勿把该文件外传）；
   - 以 UTF8 编码、ICU 中文区域（zh-CN）初始化数据库目录并建库（数据库端口 15432，仅监听本机，不对外开放）；
   - 注册两个 Windows 服务：数据库服务 `IterationBoardPG` 用 PostgreSQL 官方的 `pg_ctl register` 注册，应用服务 `IterationBoardApp` 用 WinSW 包装（依赖数据库服务先行启动）；
   - 创建每天凌晨 2:00 的自动备份计划任务；
   - 启动两个服务，并做真实健康检查（数据库进程在、15432 可连、应用页面返回 200 才算完成；任一步失败会打印日志末尾并中止，不会假报成功）。

   安装前脚本会先检测应用端口（默认 18080）是否被占用：被占时会报出占用进程名并让你当场输入另一个端口，不会装完才失败。
3. **服务默认是手动启动，不开机自启**（1.0.3 起）：安装完成时脚本会启动一次，重启电脑后服务保持停止，需要时管理员运行 `start.bat` 启动。需要开机自启的，在安装时加参数：`install.bat --autostart`。事后切换用管理员命令行：
   - 改为自启：`sc config IterationBoardPG start= auto` 和 `sc config IterationBoardApp start= auto`
   - 改回手动：`sc config IterationBoardPG start= demand` 和 `sc config IterationBoardApp start= demand`
   （注意 `start=` 后面有一个空格，是 sc 命令的固定写法。）
4. 看到「Installation complete」即安装成功。修改应用端口：运行 `install.bat 9090` 形式带端口参数安装，或安装后改 `config\application.yml` 中的 `server.port` 再重启服务（先 `stop.bat` 后 `start.bat`，均需管理员）。
4. 日常启停：管理员运行 `start.bat` / `stop.bat`；也可以在 Windows「服务」里操作上述两个服务（先启动 PostgreSQL，再启动 Application；停止顺序相反）。

## 4. 注册第一个账号（管理员）

1. 浏览器打开 `http://localhost:18080/`（把 18080 换成实际端口）。
2. 点「注册」，**第一个注册成功的账号自动成为平台管理员**。请在安装完成后立即注册，避免被他人抢注。
3. 管理员负责平台级设置（含 AI 平台开关）；其余同事随后自行注册、创建或加入小组即可。
4. 人员齐备后，如需关闭开放注册，把 `config\application.yml` 中 `app.registration-open` 改为 `false` 并重启应用服务。

## 5. 修改 AI 配置

AI 功能为可选：不配置时六项 AI 功能不可用，其余功能不受影响。

1. 用记事本打开 `config\application.yml`，找到 `ai:` 段。
2. 按注释填写服务商提供的兼容接口地址（`base-url`）、密钥（`api-key`）、文本模型（`text-model`）与视觉模型（`vision-model`），并把 `mode` 改为 `live`。
3. 保存后重启应用服务（`stop.bat` → `start.bat`）。
4. 连通性自检（见第 9 节）通过后，再在各小组的设置里逐项开启需要的 AI 功能（小组级开关默认跟随平台设置）。

注意：`config\application.yml` 含数据库口令与 AI 密钥，不要发送给无关人员，不要放进共享网盘的公开链接。

## 6. 防火墙放行

- 本机使用：无需任何放行。
- 局域网同事访问：需在 Windows Defender 防火墙放行应用端口（默认 18080）的入站 TCP。方法：设置 → 隐私和安全性 → Windows 安全中心 → 防火墙和网络保护 → 高级设置 → 入站规则 → 新建规则 → 端口 → TCP 18080 → 允许连接。
- 数据库端口 15432 **不要**放行，它只供本机应用连接。
- 同事访问地址为 `http://<服务器IP>:18080/`，服务器 IP 可在服务器上运行 `ipconfig` 查看；建议为服务器设置固定内网 IP。

## 7. 配置 HTTPS（可选，建议正式使用时配置）

平台默认以 HTTP 提供服务。需要 HTTPS 时，推荐在本机加一层反向代理，不改应用本身：

1. 准备域名与证书（单位已有证书可直接使用；也可使用免费证书服务签发，证书文件一般为 `.pfx` 或 `.crt` + `.key`）。
2. 在同一台服务器安装 Caddy（或 IIS / Nginx for Windows），以 Caddy 为例，在 `Caddyfile` 写入：

   ```
   your.domain.example {
       reverse_proxy 127.0.0.1:18080
       tls C:\certs\site.crt C:\certs\site.key
   }
   ```

3. 防火墙放行 443 端口入站；把 `config\application.yml` 的应用端口保持 18080 不变（仅本机代理访问）。
4. 重启代理服务后，用 `https://your.domain.example/` 访问验证，确认浏览器地址栏证书有效、无警告。
5. 若使用 IP 直接访问且无域名证书，浏览器会报证书警告，不建议长期使用。

## 8. 备份、恢复、升级、卸载

### 8.1 备份

- 自动备份：每天凌晨 2:00 由计划任务运行 `backup.bat`，在 `backup\<日期-时间>\` 生成数据库转储（`db.dump`）、贴图文件目录（`uploads\`，如有）与配置副本；保留最近 30 天，更早的自动删除。
- **服务未运行时自动备份会跳过**：两个服务默认手动启动，若凌晨 2:00 时服务是停止的，`backup.bat` 不会自行拉起服务，也不会报错，只在 `logs\backup.log` 记一行跳过记录后正常结束。需要这份备份时，先 `start.bat` 启动服务，再手工运行一次 `backup.bat`。
- 手工备份：随时双击 `backup.bat`（计划任务外运行会停在结果提示处）；服务未运行时它会提示先启动服务。
- 备份文件夹含配置副本（内含口令与密钥），请按敏感文件管理，并定期把 `backup\` 拷到另一台机器或移动硬盘，防单机故障。

### 8.2 恢复

1. 管理员运行 `restore.bat`，按提示输入要恢复的备份文件夹名（也可命令行带参：`restore.bat 20260101-020000`）。
2. 脚本会先对当前状态自动做一次安全备份，再停应用服务、用所选备份覆盖数据库与贴图，最后重启应用。
3. 恢复完成后刷新浏览器验证数据；若恢复失败，按脚本提示用刚生成的安全备份再次执行 restore 即可回到恢复前状态。

### 8.3 升级

1. 拿到新版离线包后解压到临时文件夹（如 `D:\ib-new`）。
2. 以管理员身份运行**新包里的** `upgrade.bat`，并带上现有安装目录：`upgrade.bat D:\iteration-board`。
3. 脚本自动：全量备份 → 停服务 → 保存旧程序到 `backup\program-<时间>\` → 替换程序文件 → 启服务（数据库结构由程序启动时自动迁移）。`config\` 与 `data\` 不会被改动，AI 等配置保持不变。
4. 升级后打开页面冒烟验证（登录、看板、事项详情各点一次）。若新版启动失败，脚本自动换回旧程序；如数据库已被新版迁移且仍异常，用 `restore.bat` 恢复升级前备份。

### 8.4 卸载

1. 管理员运行 `uninstall.bat`：停止并删除两个服务与备份计划任务。
2. 脚本会单独询问是否删除 `data\`（数据库与全部数据），默认保留。保留时日后在原目录重跑 `install.bat` 即可恢复使用（会沿用原配置与数据）。
3. 确认不再需要后，可手工删除整个安装文件夹。

## 9. AI 连通性自检

改完 AI 配置并重启后，按以下顺序自检：

1. 以管理员登录，进入任意小组的「设置 → AI」页，确认平台开关已开、六项功能状态显示为可用（不是「未配置」）。
2. 打开任意事项详情，使用「AI 速记更新」输入一句进展，确认能返回结构化预览；能返回即文本模型连通。
3. 在需求池使用「粘贴导入」，粘贴一段文本并解析，确认能拆出事项条目。
4. 打开「问答」页提一个与本组事项有关的问题，确认能给出带引用的回答。
5. 任一步失败：先看 `logs\app.log` 中 AI 相关报错——地址不可达多为网络/防火墙问题，401/403 多为密钥错误，404 多为接口地址或模型名错误，超时可调大 `config\application.yml` 中 `ai.timeout-seconds` 后重启再试。

## 10. 常见故障

| 现象 | 排查与处理 |
| --- | --- |
| 浏览器打不开登录页 | 先确认两个服务在运行（`start.bat` 或 Windows「服务」）；再确认访问端口与 `config\application.yml` 的 `server.port` 一致；局域网访问另查第 6 节防火墙。 |
| 提示端口被占用 | install.bat 安装前就会检测应用端口并报出占用进程名，可当场输入另一个端口继续。手动排查：命令行运行 `netstat -ano \| findstr :18080` 查占用进程 PID，在任务管理器结束它，或改应用端口后重启服务。数据库端口 15432 被占多为本机另装了 PostgreSQL，停掉它或联系维护人员处理。 |
| 服务启动失败 / 一闪而退 | 看 `logs\` 下的应用日志与 PostgreSQL 日志，末尾几行即失败原因；常见为配置写错（YAML 缩进、口令占位符未替换——重新运行 install.bat 可修复）、磁盘满、数据目录权限被改动。 |
| PostgreSQL 起不来、提示运行库缺失 | VC++ 运行库 DLL 随包部署、无需系统安装：先确认 `runtime\pgsql\bin` 内有 `vcruntime140.dll`、`vcruntime140_1.dll`、`msvcp140.dll` 三个文件（缺失多为解压不完整或被安全软件隔离，重新解压完整安装包、或重新套用最新补丁后，再运行 `start.bat`）；1.0.1 及更早版本留下的 `runtime\vc_redist.x64.exe` 不再使用，可忽略。 |
| 页面能开但登录/数据报错 | 多为数据库服务未启动：先在「服务」里启动 `Iteration Board - PostgreSQL`，再重启应用服务。 |
| 忘记管理员密码 | 由管理员本人在登录页走「忘记密码」流程（如已开启）；无法自助时联系平台维护人员按运维流程重置，不要直接改数据库。 |
| 备份任务没执行 | 在「任务计划程序」确认 `IterationBoardBackup` 任务存在且启用；凌晨 2:00 服务器需处于开机状态，关机错过的备份不会补跑，可手工运行 `backup.bat` 补一次。若任务显示成功但没有新备份文件夹，多半是当时服务未运行被跳过——查 `logs\backup.log` 有无 `[SKIP]` 记录，属正常行为（见 8.1）。 |
| 重启电脑后平台打不开 | 1.0.3 起两个服务默认**手动启动**，重启后保持停止，属预期行为：管理员运行 `start.bat` 即可。想恢复开机自启见第 3 节的 `sc config` 命令，或重装时加 `--autostart`。 |
| install.bat 双击闪退（1.0.2 及更早补丁） | 旧版脚本有两处括号未转义的缺陷，1.0.3 已修复：套用最新补丁（1.0.2→1.0.3 或 1.0.1→1.0.3 累积补丁）覆盖后重新以管理员身份运行即可；闪退发生在写配置之前，不会留下半成品配置。 |
| 浏览器打开首页显示一段 401 的 JSON | 1.0.3 之前版本的缺陷（前端页面被接口的安全规则拦住），套用 1.0.3 补丁换新 jar 并重启应用服务即修复。 |
| 数据库服务显示已启动但应用连不上（1.0.2 及更早） | 旧版用 WinSW 以系统身份直接拉起 postgres，postgres 拒绝在管理员令牌下运行、起来就退。1.0.3 改为 `pg_ctl register` 注册，套用 1.0.3 补丁并按补丁说明重跑 install.bat 即切换完成，数据保留。 |
| AI 功能显示不可用 | 按第 5 节检查配置是否填写、`mode` 是否为 `live`，并完成第 9 节自检。 |

仍解决不了时，把 `logs\` 下最新日志文件与现象描述一并交给维护人员。
